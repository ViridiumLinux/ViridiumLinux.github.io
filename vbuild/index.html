vbuild

vbuild is Viridium's primary package manager.

It provides a single interface for packages from both the official Arch repositories and the AUR.

Why vbuild exists

Arch Linux separates its official repositories from the AUR.

A common setup therefore uses:

pacman → official repositories
yay    → AUR

Viridium combines these into:

vbuild → official repositories + AUR

This is the main reason vbuild exists.

A package does not need a different command simply because it comes from the AUR.

vbuild is also designed to be faster than the traditional workflow of using pacman and then a separate AUR helper.

Command syntax

vbuild uses command-line options similar to pacman.

This is intentional.

Users familiar with Arch should already recognize most of the common operations.

Installing packages

Install a package with:

vbuild -S package

For example:

vbuild -S firefox

The package can come from the official repositories or the AUR.

Searching for packages

Search for a package with:

vbuild -Ss search-term

For example:

vbuild -Ss firefox

This is useful when the exact package name is not known.

Updating the system

Update the system with:

vbuild -Syu

This updates installed packages using the configured package sources.

Removing packages

Remove a package with:

vbuild -Rns package

This removes the selected package and cleans up dependencies that are no longer required.

For example:

vbuild -Rns firefox

Cleaning orphaned packages

Remove orphaned packages with:

vbuild -Yc

An orphaned package is a package that is no longer required by another installed package.

Common commands

Command | Description -- | -- vbuild -S package | Install a package vbuild -Ss term | Search for packages vbuild -Syu | Update the system vbuild -Rns package | Remove a package vbuild -Yc | Remove orphaned packages

AUR packages

AUR packages are handled through the same vbuild interface as packages from the official repositories.

This is one of the main differences between Viridium's package-management workflow and a normal Arch setup.

There is normally no need to run an AUR helper separately.

pacman and yay

pacman and yay are locked by default in Viridium.

This prevents package management from being split between several different tools.

Normal package operations should go through:

vbuild

If pacman or yay is run directly, Viridium can detect the command and provide the corresponding vbuild command.

Unlocking the original tools

There are cases where the original tools are required.

For example, a development script may expect normal pacman behaviour.

They can be temporarily unlocked with:

sudo viridium unlock

A custom unlock period can be specified:

sudo viridium unlock 30

The number is the unlock duration in minutes.

To lock the tools again manually:

sudo viridium lock

The tools automatically lock again when the unlock period expires.

vbuild vs pacman + AUR helper

The intended package-management layout is:

Traditional Arch:

pacman
  │
  └── official repositories

yay
  │
  └── AUR


Viridium:

vbuild
  ├── official repositories
  └── AUR

The unified setup is the main purpose of vbuild, while the faster workflow is an additional part of its design.
