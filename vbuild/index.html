<html><head></head><body><h1>vbuild</h1><p><code inline="">vbuild</code> is Viridium's primary package manager.</p><p>It provides a single interface for packages from both the <strong>official Arch repositories and the AUR</strong>.</p><h2>Why vbuild exists</h2><p>Arch Linux separates its official repositories from the AUR.</p><p>A common setup therefore uses:</p><pre><code class="language-text">pacman → official repositories yay → AUR </code></pre><p>Viridium combines these into:</p><pre><code class="language-text">vbuild → official repositories + AUR </code></pre><p>This is the main reason <code inline="">vbuild</code> exists.</p><p>A package does not need a different command simply because it comes from the AUR.</p><p><code inline="">vbuild</code> is also designed to be faster than the traditional workflow of using <code inline="">pacman</code> and then a separate AUR helper.</p><h2>Command syntax</h2><p><code inline="">vbuild</code> uses command-line options similar to <code inline="">pacman</code>.</p><p>This is intentional.</p><p>Users familiar with Arch should already recognize most of the common operations.</p><h2>Installing packages</h2><p>Install a package with:</p><pre><code class="language-bash">vbuild -S package </code></pre><p>For example:</p><pre><code class="language-bash">vbuild -S firefox </code></pre><p>The package can come from the official repositories or the AUR.</p><h2>Searching for packages</h2><p>Search for a package with:</p><pre><code class="language-bash">vbuild -Ss search-term </code></pre><p>For example:</p><pre><code class="language-bash">vbuild -Ss firefox </code></pre><p>This is useful when the exact package name is not known.</p><h2>Updating the system</h2><p>Update the system with:</p><pre><code class="language-bash">vbuild -Syu </code></pre><p>This updates installed packages using the configured package sources.</p><h2>Removing packages</h2><p>Remove a package with:</p><pre><code class="language-bash">vbuild -Rns package </code></pre><p>This removes the selected package and cleans up dependencies that are no longer required.</p><p>For example:</p><pre><code class="language-bash">vbuild -Rns firefox </code></pre><h2>Cleaning orphaned packages</h2><p>Remove orphaned packages with:</p><pre><code class="language-bash">vbuild -Yc </code></pre><p>An orphaned package is a package that is no longer required by another installed package.</p><h2>Common commands</h2> Command | Description -- | -- vbuild -S package | Install a package vbuild -Ss term | Search for packages vbuild -Syu | Update the system vbuild -Rns package | Remove a package vbuild -Yc | Remove orphaned packages

<h2>AUR packages</h2><p>AUR packages are handled through the same <code inline="">vbuild</code> interface as packages from the official repositories.</p><p>This is one of the main differences between Viridium's package-management workflow and a normal Arch setup.</p><p>There is normally no need to run an AUR helper separately.</p><h2>pacman and yay</h2><p><code inline="">pacman</code> and <code inline="">yay</code> are locked by default in Viridium.</p><p>This prevents package management from being split between several different tools.</p><p>Normal package operations should go through:</p><pre><code class="language-bash">vbuild </code></pre><p>If <code inline="">pacman</code> or <code inline="">yay</code> is run directly, Viridium can detect the command and provide the corresponding <code inline="">vbuild</code> command.</p><h2>Unlocking the original tools</h2><p>There are cases where the original tools are required.</p><p>For example, a development script may expect normal <code inline="">pacman</code> behaviour.</p><p>They can be temporarily unlocked with:</p><pre><code class="language-bash">sudo viridium unlock </code></pre><p>A custom unlock period can be specified:</p><pre><code class="language-bash">sudo viridium unlock 30 </code></pre><p>The number is the unlock duration in minutes.</p><p>To lock the tools again manually:</p><pre><code class="language-bash">sudo viridium lock </code></pre><p>The tools automatically lock again when the unlock period expires.</p><h2>vbuild vs pacman + AUR helper</h2><p>The intended package-management layout is:</p><pre><code class="language-text">Traditional Arch:

pacman │ └── official repositories

yay │ └── AUR

Viridium:

vbuild ├── official repositories └── AUR </code></pre><p>The unified setup is the main purpose of <code inline="">vbuild</code>, while the faster workflow is an additional part of its design.</p></body></html>
