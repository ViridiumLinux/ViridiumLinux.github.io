<html><head></head><body><h1>viridium</h1><p><code inline="">viridium</code> is Viridium's general system-management utility.</p><p>While <code inline="">vbuild</code> is responsible for package management, <code inline="">viridium</code> handles system-level tasks that don't belong directly in the package manager.</p><p>It provides shortcuts for common maintenance tasks, system information, diagnostics, and control over Viridium's package-management restrictions.</p><h2>Usage</h2><p>The general syntax is:</p><pre><code class="language-bash">viridium &lt;command&gt; </code></pre><p>Run:</p><pre><code class="language-bash">viridium help </code></pre><p>to display the available commands.</p><h2>Commands</h2><h3>update</h3><pre><code class="language-bash">viridium update </code></pre><p>Updates the system using <code inline="">vbuild</code>.</p><p>This is a shortcut for:</p><pre><code class="language-bash">vbuild -Syu </code></pre><p>Using <code inline="">viridium update</code> is intended for users who want a simple system-update command without having to remember the underlying <code inline="">vbuild</code> options.</p><h3>clean</h3><pre><code class="language-bash">viridium clean </code></pre><p>Cleans up unused package data, including orphaned packages.</p><p>This is a shortcut for:</p><pre><code class="language-bash">vbuild -Yc </code></pre><p>It is useful for routine system maintenance and freeing up space that is no longer needed by installed packages.</p><h3>info</h3><pre><code class="language-bash">viridium info </code></pre><p>Displays basic information about the current Viridium installation.</p><p>Information includes:</p><ul><li><p>Kernel</p></li><li><p>Hostname</p></li><li><p>Uptime</p></li><li><p>Installed package count</p></li></ul><p>This is intended as a quick overview rather than a complete hardware or system-information utility.</p><h3>doctor</h3><pre><code class="language-bash">viridium doctor </code></pre><p>Runs a series of checks against the current system.</p><p>The checks cover common problems such as:</p><ul><li><p>DNS</p></li><li><p>Disk space</p></li><li><p>Orphaned packages</p></li><li><p>Failed services</p></li><li><p>Other basic system conditions</p></li></ul><p>The output is intended to be readable and useful without requiring the user to manually check every component.</p><h3>doctor --fix</h3><pre><code class="language-bash">viridium doctor --fix </code></pre><p>Runs the normal diagnostic checks and attempts to fix problems that can be safely handled automatically.</p><p>Problems that cannot be safely fixed are reported instead.</p><p><code inline="">--fix</code> should not be treated as a replacement for manually diagnosing serious system problems.</p><h2>pacman and yay control</h2><p><code inline="">viridium</code> also controls the default lock on <code inline="">pacman</code> and <code inline="">yay</code>.</p><p>Viridium normally expects package management to go through <code inline="">vbuild</code>.</p><h3>unlock</h3><pre><code class="language-bash">sudo viridium unlock </code></pre><p>Temporarily unlocks the original <code inline="">pacman</code> and <code inline="">yay</code> commands.</p><p>A custom timeout can be supplied:</p><pre><code class="language-bash">sudo viridium unlock 30 </code></pre><p>The number specifies the unlock duration in minutes.</p><h3>lock</h3><pre><code class="language-bash">sudo viridium lock </code></pre><p>Immediately re-locks <code inline="">pacman</code> and <code inline="">yay</code>.</p><p>An unlock also expires automatically when its timeout is reached.</p><h2>Why this is separate from vbuild</h2><p><code inline="">vbuild</code> is focused on packages.</p><p><code inline="">viridium</code> is focused on the rest of the system.</p><p>Keeping these responsibilities separate means package operations can remain inside <code inline="">vbuild</code>, while system maintenance and administrative functions can be provided through <code inline="">viridium</code>.</p><p>In practice:</p><pre><code class="language-text">vbuild └── Package management

viridium ├── System maintenance ├── Diagnostics ├── System information └── Package-manager control </code></pre><h2>Command summary</h2>

Command | Description
-- | --
viridium help | Display available commands
viridium update | Update the system
viridium clean | Clean unused package data
viridium info | Display system information
viridium doctor | Run system diagnostics
viridium doctor --fix | Run diagnostics and fix supported problems
sudo viridium unlock | Temporarily unlock pacman and yay
sudo viridium unlock <minutes> | Unlock for a specified period
sudo viridium lock | Lock pacman and yay immediately
