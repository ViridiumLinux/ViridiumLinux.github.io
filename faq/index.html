Frequently Asked Questions

Is Viridium actually Arch?

Viridium is Arch-based and uses the Arch package ecosystem, including the official repositories and AUR. The main differences are Viridium's installer and management tools.

Does Viridium use the AUR?

Yes. AUR packages are handled through vbuild.

Do I need yay?

No. vbuild is designed to handle both official repository packages and AUR packages.

Why was vbuild created?

The main reason is to combine the official Arch repositories and the AUR into one package manager. It also uses a faster package-management workflow than the traditional pacman + AUR helper setup.

Can I still use pacman?

Yes. pacman is locked by default, but it can be temporarily unlocked: 
sudo viridium unlock

Can I still use yay?

Yes. yay is also locked by default and can be temporarily unlocked in the same way.

Why are pacman and yay locked?

Viridium is designed around vbuild being the single normal entry point for package management. Allowing three different package-management paths would defeat the purpose of combining the official repositories and AUR.

Does Viridium replace Arch's packages?

No. Viridium uses the Arch package ecosystem rather than maintaining an entirely separate package ecosystem.

Does Viridium support dual boot?

Yes. An existing EFI System Partition can be reused, and existing boot entries are left in place.

What bootloader does Viridium use?

Viridium uses systemd-boot on UEFI systems.

Does Viridium use systemd?

Yes.

How do I update?

Either: 
vbuild -Syu
or: 
viridium update

How do I clean the system?

viridium clean
or: 
vbuild -Yc

How do I check for problems?

viridium doctor
For automatic fixes where supported: 
viridium doctor --fix

How do I connect to Wi-Fi?

Run: 
nmtui

Where should I start if something is broken?

Run: 
viridium doctor
Then check the relevant page in this wiki.
