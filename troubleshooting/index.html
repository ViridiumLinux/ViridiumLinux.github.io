Troubleshooting

This page covers some of the more common problems encountered while using Viridium.

Start with viridium doctor

For general problems, run:

viridium doctor

It checks several common system conditions and reports anything it finds.

If supported fixes are available:

viridium doctor --fix

No network connection

Check NetworkManager:

systemctl status NetworkManager

If it is not working correctly:

sudo systemctl restart NetworkManager

For Wi-Fi:

nmtui

DNS problems

Run:

viridium doctor

You can also inspect the resolver configuration:

resolvectl status

Low disk space

Check the system:

viridium doctor

Then clean unused package data:

viridium clean

Or directly:

vbuild -Yc

Orphaned packages

Remove orphaned packages with:

viridium clean

or:

vbuild -Yc

Failed services

List failed systemd services:

systemctl --failed

Check a specific service with:

systemctl status service-name

pacman or yay will not run

This is expected behaviour.

Both commands are locked by default.

Use:

vbuild

for normal package management.

If the original tool is actually required:

sudo viridium unlock

Package installation problems

First check the network:

viridium doctor

Then retry the package operation.

For example:

vbuild -S package

If the issue involves the underlying package tools, they can be temporarily unlocked for further testing.

Boot problems

If the system does not boot, see [[Boot and UEFI]].

From another Linux environment, EFI boot entries can be checked with:

efibootmgr

Installation problems

If installation fails, check:

  • Network connectivity
  • Selected disk
  • EFI System Partition
  • Available disk space
  • Installer output

Do not retry a destructive installation without checking which disk is selected first.
