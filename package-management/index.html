Package Management

Viridium uses vbuild as its normal package-management interface.

Package sources

Viridium uses the same general package ecosystem as Arch Linux: * Official Arch repositories * Arch User Repository (AUR) vbuild handles both sources.

Official repositories

Packages available through the normal Arch repositories are installed through vbuild: 
vbuild -S package

AUR

Packages available through the AUR are also handled through vbuild. The user does not need to switch to yay or another AUR helper for normal package installation.

Package management model

The intended model is: 
                 vbuild
                /      \
               /        \
      Arch repositories  AUR
rather than: 
pacman ──→ Arch repositories
yay ─────→ AUR
This provides one entry point for package management.

Why pacman and yay are locked

pacman and yay are disabled for normal direct use. The purpose is to prevent multiple package-management paths from being used at the same time. For example, a normal Viridium system should generally be managed through: 
vbuild -Syu
rather than independently running pacman and yay. This also allows Viridium's package-management workflow to remain consistent.

Command translation

If a user runs pacman or yay directly, Viridium can detect the command and provide the equivalent vbuild command. This makes accidentally using the wrong command less disruptive.

Unlocking

When direct access to the original tools is actually required: 
sudo viridium unlock
A custom duration can be specified: 
sudo viridium unlock 30
Lock them immediately with: 
sudo viridium lock
The tools automatically lock again after the timeout.

When should pacman or yay be unlocked?

The normal answer is: only when something specifically requires them. Examples include: * Testing package-management behaviour * Development * Scripts expecting the original commands * Debugging package-manager issues For normal package installation and updates, use vbuild.
