Install Viridium Linux

<html><head></head><body><h1>Architecture</h1><p>Viridium is built around the Arch Linux package ecosystem with a small set of custom tools layered on top.</p><p>The project does not attempt to replace the underlying Arch system. Instead, Viridium provides its own installation and management workflow while continuing to use the existing Arch infrastructure.</p><h2>Overview</h2><p>The main components are:</p><pre><code class="language-text"> Viridium Linux │ ┌─────────────────┴─────────────────┐ │ │ Installation System │ │ vinstall ┌───────────┴───────────┐ │ │ vbuild viridium │ │ ┌────────┴────────┐ ┌──────┴──────┐ │ │ │ │ Arch repos AUR Maintenance Diagnostics </code></pre><p>Each component has a specific purpose.</p><h2>vinstall</h2><p><code inline="">vinstall</code> is responsible for creating a Viridium installation.</p><p>Its responsibilities include:</p><ul><li><p>Disk selection</p></li><li><p>Partition handling</p></li><li><p>Filesystem setup</p></li><li><p>Kernel installation</p></li><li><p>Base system installation</p></li><li><p>Hostname configuration</p></li><li><p>Timezone configuration</p></li><li><p>User creation</p></li><li><p><code inline="">sudo</code> configuration</p></li><li><p>EFI configuration</p></li><li><p>Bootloader installation</p></li></ul><p>The installer runs from the Viridium live environment and installs the system onto the selected disk or existing partitions.</p><p>It is not responsible for normal system management after installation.</p><h2>vbuild</h2><p><code inline="">vbuild</code> is the package-management layer.</p><p>Its main purpose is combining the two package sources used by Viridium:</p><pre><code class="language-text">Official Arch repositories + AUR ↓ vbuild </code></pre><p>A traditional Arch setup often separates these:</p><pre><code class="language-text">pacman → official repositories yay → AUR </code></pre><p>Viridium provides one interface instead.</p><h3>Package management flow</h3><p>A simplified package-management flow is:</p><pre><code class="language-text">User │ ▼ vbuild │ ├──► Official repositories │ └──► AUR </code></pre><p>This is the central design decision behind <code inline="">vbuild</code>.</p><p>It also allows Viridium to implement a faster package-management workflow than the traditional <code inline="">pacman</code> + AUR helper setup.</p><h2>viridium</h2><p><code inline="">viridium</code> sits above the lower-level system tools.</p><p>It provides commands for:</p><ul><li><p>Updating</p></li><li><p>Cleaning</p></li><li><p>Diagnostics</p></li><li><p>System information</p></li><li><p>Package-manager locking</p></li><li><p>Package-manager unlocking</p></li></ul><p>It can also act as a simple frontend for common <code inline="">vbuild</code> operations.</p><p>For example:</p><pre><code class="language-text">viridium update │ ▼ vbuild -Syu </code></pre><p>The purpose is to provide simple commands for common operations without adding another package-management implementation.</p><h2>pacman and yay</h2><p>The original Arch package tools still exist underneath the Viridium package-management system.</p><p>They are locked by default rather than removed.</p><p>The relationship is therefore:</p><pre><code class="language-text"> Package management │ vbuild / \ / \ Arch repositories AUR

pacman / yay │ compatibility / temporary use </code></pre><p><code inline="">viridium</code> controls whether the original tools are accessible.</p><p>They can be temporarily unlocked when compatibility, development, or debugging requires them.</p><h2>NetworkManager</h2><p>Viridium uses NetworkManager for network configuration.</p><p>NetworkManager is separate from the Viridium package-management tools and provides the normal Linux networking layer.</p><p>Common interfaces include:</p><pre><code class="language-text">nmtui nmcli </code></pre><h2>systemd</h2><p>Viridium uses systemd for system initialization and service management.</p><p>This includes normal systemd functionality such as:</p><pre><code class="language-bash">systemctl </code></pre><p>Services can therefore be managed using the standard systemd tools.</p><h2>systemd-boot</h2><p>Viridium uses systemd-boot for UEFI booting.</p><p>The installer places the required boot files on the EFI System Partition and creates the Viridium boot entry.</p><p>Existing EFI entries can remain alongside it.</p><h2>Design principles</h2><p>Viridium's architecture is based around a few simple ideas.</p><h3>Keep the Arch ecosystem</h3><p>Viridium does not need to maintain a completely separate package ecosystem.</p><p>The Arch repositories and AUR already provide the packages required by the system.</p><h3>One package manager</h3><p>Normal package management goes through <code inline="">vbuild</code>.</p><p>This combines the official repositories and AUR and avoids requiring separate tools for normal package operations.</p><h3>Keep system tools separate</h3><p><code inline="">vinstall</code>, <code inline="">vbuild</code>, and <code inline="">viridium</code> have different responsibilities.</p><pre><code class="language-text">vinstall → installation vbuild → packages viridium → system management </code></pre><p>This separation keeps each component relatively focused.</p><h3>Don't remove the underlying tools</h3><p>Viridium does not permanently remove <code inline="">pacman</code> or <code inline="">yay</code>.</p><p>They remain available for compatibility and development purposes, but are locked during normal operation.</p><h2>Component summary</h2> Component | Responsibility -- | -- vinstall | Installation vbuild | Package management viridium | System management pacman | Underlying Arch package manager yay | AUR helper / compatibility NetworkManager | Networking systemd | System and services systemd-boot | UEFI boot

<p>This separation is the basis of the Viridium userspace.</p></body></html>
