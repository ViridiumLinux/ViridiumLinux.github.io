Architecture

Viridium is built around the Arch Linux package ecosystem with a small set of custom tools layered on top.

The project does not attempt to replace the underlying Arch system. Instead, Viridium provides its own installation and management workflow while continuing to use the existing Arch infrastructure.

Overview

The main components are:

                         Viridium Linux
                                │
              ┌─────────────────┴─────────────────┐
              │                                   │
          Installation                         System
              │                                   │
          vinstall                     ┌───────────┴───────────┐
                                       │                       │
                                    vbuild                 viridium
                                       │                       │
                              ┌────────┴────────┐       ┌──────┴──────┐
                              │                 │       │             │
                         Arch repos            AUR   Maintenance   Diagnostics

Each component has a specific purpose.

vinstall

vinstall is responsible for creating a Viridium installation.

Its responsibilities include:

  • Disk selection

  • Partition handling

  • Filesystem setup

  • Kernel installation

  • Base system installation

  • Hostname configuration

  • Timezone configuration

  • User creation

  • sudo configuration

  • EFI configuration

  • Bootloader installation

The installer runs from the Viridium live environment and installs the system onto the selected disk or existing partitions.

It is not responsible for normal system management after installation.

vbuild

vbuild is the package-management layer.

Its main purpose is combining the two package sources used by Viridium:

Official Arch repositories
            +
           AUR
            ↓
         vbuild

A traditional Arch setup often separates these:

pacman → official repositories
yay    → AUR

Viridium provides one interface instead.

Package management flow

A simplified package-management flow is:

User
 │
 ▼
vbuild
 │
 ├──► Official repositories
 │
 └──► AUR

This is the central design decision behind vbuild.

It also allows Viridium to implement a faster package-management workflow than the traditional pacman + AUR helper setup.

viridium

viridium sits above the lower-level system tools.

It provides commands for:

  • Updating

  • Cleaning

  • Diagnostics

  • System information

  • Package-manager locking

  • Package-manager unlocking

It can also act as a simple frontend for common vbuild operations.

For example:

viridium update
       │
       ▼
vbuild -Syu

The purpose is to provide simple commands for common operations without adding another package-management implementation.

pacman and yay

The original Arch package tools still exist underneath the Viridium package-management system.

They are locked by default rather than removed.

The relationship is therefore:

                    Package management
                           │
                         vbuild
                       /       \
                      /         \
             Arch repositories   AUR
                      
              pacman / yay
                    │
             compatibility /
              temporary use

viridium controls whether the original tools are accessible.

They can be temporarily unlocked when compatibility, development, or debugging requires them.

NetworkManager

Viridium uses NetworkManager for network configuration.

NetworkManager is separate from the Viridium package-management tools and provides the normal Linux networking layer.

Common interfaces include:

nmtui
nmcli

systemd

Viridium uses systemd for system initialization and service management.

This includes normal systemd functionality such as:

systemctl

Services can therefore be managed using the standard systemd tools.

systemd-boot

Viridium uses systemd-boot for UEFI booting.

The installer places the required boot files on the EFI System Partition and creates the Viridium boot entry.

Existing EFI entries can remain alongside it.

Design principles

Viridium's architecture is based around a few simple ideas.

Keep the Arch ecosystem

Viridium does not need to maintain a completely separate package ecosystem.

The Arch repositories and AUR already provide the packages required by the system.

One package manager

Normal package management goes through vbuild.

This combines the official repositories and AUR and avoids requiring separate tools for normal package operations.

Keep system tools separate

vinstall, vbuild, and viridium have different responsibilities.

vinstall   → installation
vbuild     → packages
viridium   → system management

This separation keeps each component relatively focused.

Don't remove the underlying tools

Viridium does not permanently remove pacman or yay.

They remain available for compatibility and development purposes, but are locked during normal operation.

Component summary

Component | Responsibility -- | -- vinstall | Installation vbuild | Package management viridium | System management pacman | Underlying Arch package manager yay | AUR helper / compatibility NetworkManager | Networking systemd | System and services systemd-boot | UEFI boot

This separation is the basis of the Viridium userspace.
